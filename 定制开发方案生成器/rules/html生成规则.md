# HTML 可视化方案生成规则

## 文件结构

必须是**单文件 HTML**，可直接双击在浏览器打开，包含：
- 内联 CSS（无外部依赖）
- 内联 SVG 图标（无外部图片，必要时用 base64）
- 响应式（PC 优先，平板可读）

## 先选叙事结构（两种模式，二选一）

> **生成 HTML 前，必须先根据场景类型与材料语气，判断用哪种叙事结构。** 选错结构会让方案"答非所问"。

| 模式 | 适用场景 | 语气 | 章节骨架 |
|---|---|---|---|
| **A. 营销式**（默认） | 已明确要做的系统、对客户决策层"种草"、需要 ROI 说服 | 卖点驱动、价值主张 | Hero → 痛点 → 方案总览 → 流程时间线 → 泳道 → Mockup → 多视图 → KPI/ROI → 甘特图 → CTA |
| **B. 咨询诊断式** | 需求尚在梳理、服务商先"诊断+建议"、强调专业方法论（如制造业积分激励、流程重构） | 顾问视角、先诊断后开方 | 客户阶段判断 → 需求洞察 → 流程拆解 → 建议建设模块 → 自动化与权限 → 实施路径 → 待确认问题 |

**判断依据**：
- 材料是"服务商方案/需求总结/诊断报告"语气，含"现状/核心问题/建设目标/待确认" → 用 **B 咨询诊断式**
- 材料是"已定方案、要打动客户签约" → 用 **A 营销式**
- 拿不准时默认 **A**；但**积分激励 / 流程重构 / 管理咨询**类优先 **B**

## 模式 A · 营销式 — 必备章节（按顺序）

### 1. 顶部 Hero 区
```
┌────────────────────────────────────┐
│ [Logo] 方案生成器    [客户名 V1]   │  ← 导航条
├────────────────────────────────────┤
│                                    │
│  行业 · 场景 · 一句话价值主张       │  ← 大标题（48pt）
│  副标题：解决 X 个核心痛点          │
│  [立即沟通]  [查看演示]             │  ← CTA
│                                    │
└────────────────────────────────────┘
```

### 2. 客户痛点卡片区
- 3-4 张卡片，每张包含：图标 + 痛点标题 + 描述 + 影响数据
- 卡片网格：桌面 3-4 列，平板 2 列，手机 1 列
- 颜色：图标用警示色 `#FF6B35`

### 3. 解决方案总览
- 一句话总览 + 三大支柱图示
- 每个支柱：标题 + 1 段描述 + 配图占位

### 4. 业务流程时间线
- 水平时间线，5-8 个节点
- 节点：圆形 + 图标 + 名称 + 简述
- 痛点节点用警示色高亮
- 流程节点用主色

### 5. 角色协同泳道图
- 横轴：时间/阶段
- 纵轴：参与角色（客户/服务商）
- 每个角色有自己的"动作轨道"
- 跨角色交接用连接线

### 6. 核心功能页面 mockup
- 4-6 个**真实页面截图风格**的 mockup
- 用 HTML/CSS 画出来（不要放占位图）
- 每个 mockup 配 1 段功能说明

### 7. 智能表格多视图展示
- 3-5 个表格视图缩略图
- 每个视图：表头 + 5-8 行示例数据 + 关键字段标注

### 8. 价值与 ROI 看板
- 4 个大数字 + 简短说明
- 数字格式：节省 X 万、效率 +X%、差错率 -X%
- 必须有"目标值 vs 实际值"对比

### 9. 实施计划甘特图
- 横轴：周次（4-8 周）
- 纵轴：阶段（需求/设计/开发/测试/上线）
- 不同阶段用不同颜色

### 10. 底部 CTA + 版权
- "下一步"按钮
- 服务商联系方式
- 版权信息

## 模式 B · 咨询诊断式 — 必备章节（按顺序）

> 顾问视角：**先诊断现状，再开处方**。每一章都体现"我们理解你的处境 → 我们的专业判断 → 我们建议这样做"。范例见 `examples/福鸿客户/`、`examples/贵州宏立城/`。

### 00. Hero 速览区（开篇，必做）
- 顶部导航条：客户名 + 锚点导航（需求洞察/方案架构/智能表格/实施路径）
- 大标题：客户全称 + 场景标题（如"固定资产盘点与折旧管理方案"）+ 一句话规模/范围描述
- **"方案核心链路"图**：用 3-4 个箭头串起的步骤卡概括整个方案（如 资产入库 → 分类匹配折旧 → 流转留痕 → 报废下账闭环）
- **关键数字卡**：3-4 个大数字概括方案体量（如 2500 员工规模 / 4+1 表格看板架构 / 按月 折旧颗粒度 / 闭环 报废处置）

### 01. 客户阶段判断（需求洞察）
- 两栏或三栏：**现状描述 / 核心问题**（可含建设目标）
- 用客户自己的话描述现状（来自 B/C 材料），不要替客户编
- 核心问题用警示色

### 02. 推荐建设范围（一期/二期/暂不建议 三栏并列）
- **三栏卡片**：`一期必做` / `二期扩展` / `暂不建议`
- 一期必做：列出本期要交付的表与视图
- 二期扩展：客户提到但本期不做的（如其他行政审批、二维码盘点、系统对接）
- 暂不建议：明确不做的边界（如"不替代完整财务系统""不做复杂会计凭证"）
- 这一栏直接对应 docx 第二节"方案边界"，是控制交付范围的关键

### 03. 企业微信能力与定制服务架构
- 用 6 个左右**带序号的能力卡片**呈现方案模块（如 资产建库/分类折旧/流转登记/部门回写/报废汇总/数据看板）
- 每张：序号 + 模块名 + 一句话能力描述
- 模块要与 xlsx 的 Sheet / docx 的功能一一对应

### 04. 智能表格交付设计
- 表格形式列出全部 Sheet：表名 | 用途 | 关键字段/能力 | 使用角色
- 与 docx 第六节、xlsx 完全对齐

### 05. 方案价值
- 6 个左右价值点卡片（如 盘点成本下降/流转可追溯/折旧更及时/报废闭环/权限清晰/二期可扩展）
- 每张：价值标题 + 一句话说明
- B 模式不堆 ROI 大数字，用"定性价值卡"即可

### 06. 实施路径建议
- 表格或时间线：阶段 | 工作内容 | 客户配合 | 输出物
- 通常 4 阶段：需求确认 → 表格搭建 → 规则配置 → 上线优化
- 结尾一句免责：本方案为售前需求确认稿，未确认内容不纳入一期交付承诺

> 模式 B 不需要营销式的 ROI 大字看板和甘特图。两种模式共用下方"组件规范/数字与文案/交互"要求。
> 注：章节数量可按场景伸缩（福鸿 8 章偏诊断，宏立城 6 章偏范围确认），但 **Hero 速览 + 推荐建设范围三栏 + 实施路径** 是 B 模式的标志性结构。

## 组件规范

### 卡片
```css
.card {
  background: #FFFFFF;
  border: 1px solid #E5E7EB;
  border-radius: 12px;
  padding: 24px;
  box-shadow: 0 2px 8px rgba(0,0,0,0.04);
  transition: all 0.2s;
}
.card:hover {
  transform: translateY(-2px);
  box-shadow: 0 8px 24px rgba(0,0,0,0.08);
}
```

### 按钮
```css
.btn-primary {
  background: #1E5AFF;
  color: #FFF;
  padding: 12px 24px;
  border-radius: 8px;
  font-weight: 600;
}
.btn-secondary {
  background: #FFF;
  color: #1E5AFF;
  border: 1px solid #1E5AFF;
  /* ... */
}
```

### 时间线节点
```css
.timeline-node {
  width: 48px;
  height: 48px;
  border-radius: 50%;
  background: #1E5AFF;
  color: #FFF;
  display: flex;
  align-items: center;
  justify-content: center;
  /* ... */
}
.timeline-node.pain {
  background: #FF6B35;
}
```

## 数字与文案要求

- 数字必须**带单位**（如"节省 50 万"不要写"节省 500000"）
- 百分比保留 1 位小数
- 金额用 ¥ 前缀 + 千分位
- 句子长度：中文不超过 30 字
- 关键概念用 **粗体** + 主色

## 交互（可选但加分）

- 滚动渐入动画（Intersection Observer）
- 卡片 hover 上浮
- 流程图节点点击展开详情
- 数字滚动计数（CountUp.js 风格，可手写）
- 移动端汉堡菜单

## 文件大小

- 单文件 < 2MB
- 尽量不引入外部 JS/CSS（如果必须，注明 CDN）
- 优先用 CSS 实现视觉，必要时用 inline SVG
