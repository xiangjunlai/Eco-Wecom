# 输入解析规则

接到一堆客户材料后，按以下流程**识别、分类、抽取**。任何**未抽取到**的关键字段必须**显式标记**为"⚠️ 待确认"，不得自行编造。

## 第一步：识别输入材料类型

按文件路径和标题，把每份材料归类到 A/B/C/D 四类之一：

### A 类：知识库文档
**识别特征**：
- 路径含 `knowledge_*/`
- 文件名含"行业""领域""基础""入门"
- 内容以解释性文字为主，少量人称

**典型文件**：
- `knowledge_家装/家装行业.docx`
- `knowledge_外贸/服装外贸.docx`
- `餐饮行业基础知识.md`

**抽取内容**：
- 行业专业术语
- 行业典型流程节点
- 行业典型角色
- 行业核心痛点
- 行业关键指标

### B 类：需求沟通记录
**识别特征**：
- 路径含 `requirement_*/`
- 文件名含"沟通记录""需求沟通""第 N 题"
- 标题里有"服务商名@客户名_日期_...-N 次需求沟通记录"
- 内容通常以"客户方""我方""需求""痛点"等词为骨架

**典型文件**：
- `requirement_家装/第6题_吴sir@杭州装企云网络科技有限公司_20260512_贵州亿选装饰-...-1次需求沟通记录_1.docx`

**抽取内容（最高优先级）**：
- **客户名**（全称 + 简称）
- **服务商名**（全称 + 简称）
- **沟通日期**
- **客户方参与人**
- **服务商方参与人**
- **客户行业 + 业务背景**
- **核心痛点清单**
- **关键场景**
- **量化目标**（订单量、节省金额、提效百分比等）
- **决策时间节点**

### C 类：服务商需求描述
**识别特征**：
- 文件名含"服务商""需求描述""需求总结"
- 内容以"我方""我们""方案""建议"等词为骨架
- 是服务商对客户需求的**二次解读**

**典型文件**：
- `服务商对客户需求描述(2).docx`
- `服务商需求总结.docx`

**抽取内容**：
- 服务商对客户痛点的**重新组织**（可能用了更专业术语）
- 服务商视角的**方案设计思路**
- 服务商**自有的方法论**（如"前端数据分析"是服务商标签）
- 与 B 类可能**有差异**，需要交叉验证

### D 类：结果范例（可选）
**识别特征**：
- 路径含 `result_*/`
- 文件名通常是已完成的方案文件
- 用于风格参考，**不是输入**（是上次输出的范例）

**处理方式**：
- 提取风格特征：配色、章节结构、语气
- **不抽取**其中的客户/服务商信息（那是上一个项目的）

## 第二步：抽取必填字段

无论输入材料如何，必须尝试抽取以下字段：

### 客户基础信息
| 字段 | 抽取来源 | 兜底 |
|---|---|---|
| 客户全称 | B 类标题/正文 | "⚠️ 待确认" |
| 客户简称 | 全称简写 | 用全称 |
| 所属行业 | B/C 类正文 | "⚠️ 待确认" |

### 服务商基础信息
| 字段 | 抽取来源 | 兜底 |
|---|---|---|
| 服务商全称 | B 类标题（@前的部分）/C 类正文 | `[服务商名称待填]` |
| 服务商简称 | 全称简写 | 用全称 |
| 服务商联系人 | B 类正文 | "⚠️ 待确认" |

### 业务信息
| 字段 | 抽取来源 | 兜底 |
|---|---|---|
| 核心场景 | B/C 类正文 | "⚠️ 待确认" |
| 关键痛点 | B/C 类 | 提供 4 个通用痛点兜底 |
| 量化目标 | B/C 类中的具体数字 | 标"⚠️ 待客户提供" |
| 参与角色 | B/C 类 | 通用角色兜底 |
| 时间节点 | B 类 | 标"⚠️ 待确认" |

## 第三步：交叉验证

如果 A/B/C 三类材料都有，做交叉印证：

| 验证项 | 怎么验 | 不一致时 |
|---|---|---|
| 客户名 | B 类 vs C 类 | 以 B 为准，C 标"⚠️ 与沟通记录不一致" |
| 行业术语 | A 类（专业术语） vs B 类（客户用词） | 在 docx 中**优先用 A 类的术语**（更专业） |
| 痛点描述 | B 类（原话） vs C 类（服务商解读） | docx 痛点章节用 B 原话，方案章节用 C 解读 |
| 量化数据 | B vs C | 取交集（都提到的才用），单独提到的标"⚠️ 单一来源" |

## 第四步：识别场景类型

基于 B/C 类材料，判断本次需求属于哪种场景：

| 场景类型 | 关键词 | HTML 模板 | xlsx Sheet | docx 章节侧重 |
|---|---|---|---|---|
| **数据分析** | 数据看板/BI/驾驶舱/可视化/报表/分析 | 数据大屏风格 | 数据看板 + 多维分析 + 报表 | 数据源 + 分析维度 + 看板设计 |
| **流程协同** | 审批/工单/订单/打样/巡检/流转 | 流程时间线 | 状态机 + 角色泳道 | 端到端流程 + 状态变更 + 自动化 |
| **客户/销售** | CRM/客户/商机/漏斗/跟进 | 客户视图 + 销售漏斗 | 客户档案 + 商机 + 跟进 | 客户主数据 + 销售流程 |
| **人力/行政** | HR/招聘/考勤/报销/培训 | 流程 + 人员视图 | 人员 + 流程 + 报表 | 制度 + 流程 + 培训 |
| **通用兜底** | 上述都不像 | 通用业务模板 | 通用 7 个 Sheet | 通用 10 章 |

## 第五步：判断是否需要第 ④ 份 Prompt

只有以下场景才生成第 ④ 份 **搭建 Prompt**（搭建对象一律为**企业微信**生态，不涉及友商平台）：
- 数据分析（需要在企业微信内搭智能表格）
- 流程协同（需要在企业微信工作台搭建自建应用）
- 客户/销售（需要搭企业微信智能表格 CRM）

不需要的场景（生成 3 份即可）：
- 纯咨询方案
- 培训方案
- 战略规划

## 缺失材料处理

| 缺失类型 | 处理方式 |
|---|---|
| A 类缺失 | 退化为通用业务术语，docx 中所有"专业术语"用通用词 |
| B 类缺失 | 只能依赖 C 类，C 类也没提 → 客户名/场景全部"⚠️ 待确认" |
| C 类缺失 | 直接基于 B 类生成，docx 中**不引用**服务商视角的解读 |
| A+B+C 全部缺失 | 拒绝生成，提示用户至少提供 1 份材料 |
| D 类缺失 | 退化为"按规则默认风格" |

## 与知识库的交叉印证

有 A 类材料时：
- 提取**专业术语** → 用于三件套统一用词
- 提取**典型流程** → 用于 HTML 流程图骨架
- 提取**常见角色** → 用于角色清单补充
- 提取**核心指标** → 用于数据看板设计

**输出物**：行业知识与客户需求映射表（仅在 AI 内部思考，不直接写到交付物里）
