## 〇、场景类型识别（按优先级判断）

> 任何行业都先判断属于哪种**场景类型**，再选对应的模板骨架。

| 场景类型 | 典型关键词 | 模板特征 |
|---|---|---|
| **数据分析** | 数据看板/BI/驾驶舱/可视化/数据源/数据指标/数据维度 | 数据大屏风格、多维分析、KPI 看板、字段映射 |
| **流程协同** | 审批/工单/订单/打样/巡检/流转/状态 | 流程时间线、角色泳道、状态机 |
| **客户/销售** | CRM/客户/商机/漏斗/跟进/线索 | 客户主数据、销售漏斗、跟进记录 |
| **人力/行政** | HR/招聘/考勤/报销/培训/绩效 | 人员主数据、流程审批、报表统计 |
| **通用兜底** | 上述都不像 | 通用业务模板 |

## 六、制造业 · 员工改善提报与积分激励 ✅ 已沉淀（基于福鸿客户用例）

> 属于"人力/行政"大类下的**积分激励**子场景。核心技术特征是**多表通过关联字段自动汇总积分与库存**（跨表关联），是数据分析/流程协同之外的第三种典型骨架。

### 核心流程节点
员工提报改善建议 → 管理员审核 → 落实人确认落实 → 积分自动发放（提报人 +N、落实人 +N） → 员工用积分兑换奖品 → 管理员确认领取 → 奖品库存自动扣减 ← 采购入库自动补库存

### 角色
- **员工（全员）**：提报改善建议、查看个人积分、兑换奖品
- **落实人**：负责把改善建议落地（可以是提报人本人，也可以是指定他人）
- **人事/管理员**：维护人员表、审核提报、确认奖品领取、维护积分规则
- **采购**：负责奖品采购入库，维护奖品库存
- **管理层/老板**：查看部门改善排名、个人积分排行榜、改善成效统计

### 6 表联动结构（核心设计，**这是本场景的灵魂**）

| 表 | 作用 | 关键字段 | 关联关系 |
|---|---|---|---|
| **① 改善提报表** | 记录每条改善建议 | 提报人、部门、改善内容、落实人、状态、提报积分、落实积分 | 提报人/落实人 → 人员积分表 |
| **② 部门排名表** | 按部门汇总改善数与积分 | 部门、改善条数、累计积分、排名 | rollup 自 ① 改善提报表 |
| **③ 人员积分表** | 每个员工的积分账户 | 姓名、部门、累计获得积分、已用积分、可用积分（=累计−已用） | 累计积分 ← ①；已用积分 ← ⑥ |
| **④ 奖品库存表** | 奖品当前库存 | 奖品名、所需积分、当前库存、已兑数量 | 库存 ← ⑤ 入库增加、⑥ 领取减少 |
| **⑤ 采购入库表** | 奖品采购入库记录 | 奖品名、入库数量、入库日期、采购人 | 入库数量 → ④ 库存 +N |
| **⑥ 奖品领取表** | 员工兑换记录 | 领取人、奖品名、消耗积分、领取日期、状态 | 消耗积分 → ③ 已用积分；领取 → ④ 库存 −1 |

### 跨表关联汇总规则（用 rollup/lookup 实现）
```
① 改善提报（状态=已落实）  →  ③ 人员积分表.累计积分（提报人 +提报积分，落实人 +落实积分）
① 改善提报                 →  ② 部门排名表.累计积分 / 改善条数（按部门 rollup）
⑥ 奖品领取（状态=已领取）  →  ③ 人员积分表.已用积分（按领取人 sum 消耗积分）
③ 人员积分表.可用积分       =  累计积分 − 已用积分（公式字段）
⑤ 采购入库                 →  ④ 奖品库存.当前库存（+入库数量）
⑥ 奖品领取                 →  ④ 奖品库存.当前库存（−1 / −数量）
```

### 状态枚举
- **提报状态**：待审核 / 已通过 / 已驳回 / 落实中 / 已落实
- **落实状态**：待落实 / 落实中 / 已落实 / 无需落实
- **领取状态**：待审核 / 已确认 / 已领取 / 已取消
- **库存状态**：充足 / 偏低 / 缺货

### 积分规则（示例，需从材料抽取真实数值）
- 提报一条被采纳的改善建议：提报人 +X 分
- 落实一条改善建议：落实人 +Y 分
- 兑换奖品：消耗对应积分，可用积分不足则无法兑换

### 数据看板常用 KPI
- 本月改善提报数 / 已落实数 / 落实率
- 部门改善排名 Top N / 个人积分排行 Top N
- 累计发放积分 / 累计兑换积分 / 奖品库存预警数

### 范例
`examples/福鸿客户/`（**四件套齐全：HTML + docx + xlsx + 搭建 Prompt**，跨表关联与积分激励范本）

## 七、金融 / 担保 · 助贷订单管理与资金协同 ✅ 已沉淀（基于广州鹏宁担保用例）

> 属于"流程协同 + 资金闭环"复合场景。核心技术特征是**三层表结构（基础库 + 流水表 + 回写汇总）**与**"待付 = 应付 − 已付"资金三态闭环**，是比单纯积分激励更复杂的多表关联范式。

### 核心流程节点
业务员进件录单 → 中台文员复审（通过/退回/重填） → 银行放款（成功/拒绝） → 车辆上牌 → 抵押归档（超期预警） → 银行返款收款 → 经销商/渠道付款 → 员工提成结算下发

### 角色（6 类）
- **销售/业务员**：进件录单、上传证件、查看本人订单
- **销售主管**：查看下属订单与业绩（原则只读）
- **中台文员**：复审订单、维护审批状态（非固定分配）
- **后台/归档专员**：放款后处理上牌、抵押、归档（相对固定）
- **财务**：维护银行收款、经销商付款、员工提成下发等资金记录
- **管理员/管理层**：全量查看、看板、权限配置

### 三层表结构（核心设计，**这是本场景的灵魂**）

| 层 | 表 | 作用 | 关键字段 |
|---|---|---|---|
| **业务主表** | 订单管理 | 一笔助贷订单的全生命周期，承载 50+ 字段与附件 | 审批状态、放款状态、归档情况、客户证件、贷款信息、资金字段 |
| **基础数据库** | 贷款产品库 / 经销商库 / 渠道商库 / 员工库 | 供订单关联选择，并被回写汇总业绩与应付 | 名称、关联记录、应付/已付/待付、总提成 |
| **流水明细表** | 银行收款管理 / 经销商付款 / 员工提成下发管理 | 记录每一笔资金往来，回写基础库 | 对象选择、付款金额、登记人、登记时间、登记年月 |

### 资金三态闭环（用 rollup/公式实现）
```
订单管理.银行应收     →（按银行/产品 rollup）→ 贷款产品库.银行应付
银行收款管理.付款金额 →（按银行 rollup）     → 贷款产品库.已付总额
贷款产品库.待付金额    = 银行应付 − 已付总额（公式）

订单管理.供应商提成   →（按经销商 rollup）   → 经销商库.经销商总提成
经销商付款.付款金额   →（按经销商 rollup）   → 经销商库.已付总额
经销商库.待付金额      = 经销商总提成 − 已付总额（公式）

订单管理.员工提成     →（按业务员 rollup）   → 员工库.员工总提成
员工提成下发.发放金额 →（按员工 rollup）     → 员工库.累计发放金额
员工库.待发金额        = 员工总提成 − 累计发放金额（公式）
```
> 通用范式：**应付/应收（来自业务主表汇总）− 已付/已收（来自流水表汇总）= 待付/待收（公式）**。任何"对多方结算"的业务都可套用。

### 状态枚举
- **中台审批**：待复审 / 审批通过 / 退回 / 重填
- **放款状态**：待放款 / 成功放款 / 拒绝放款
- **车辆上牌**：待上牌 / 已上牌
- **归档情况**：待归档 / 抵押归档 / 超期归档

### 关键字段与录入特征
- **OCR 自动识别**：身份证正反面上传后自动带出姓名/民族/身份证号/住址/有效期
- **1 对 1 自动带出**：选择贷款产品后自动带出对应申请银行
- **关联搜索选择**：经销商/渠道商有几百家，禁止全量铺开，必须搜索选择
- **人员自动带出**：选业务员后自动带出其业务主管、后台文员（相对固定）
- **字段分组**：订单表 50+ 字段按"状态流转/客户证件/居住工作/紧急联系人/共借人/贷款信息/车辆信息/角色信息/渠道经销/资金字段/系统信息"分组

### 数据看板常用 KPI
- 订单总数 / 待复审 / 已通过 / 成功放款 / 拒绝放款 / 待归档 / 超期归档
- 业务员进件数 / 放款数 / 转化率 / 主贷款总额
- 各经销商进件数与提成 / 各银行应收已付待付 / 渠道推荐数
- 员工提成待发/已发

### 范例
`examples/广州鹏宁担保/`（**四件套齐全 + 输入参考**，咨询诊断式 HTML + 三层资金闭环 xlsx + 详尽搭建 Prompt）

## 八、行政 / 资产 · 固定资产盘点与折旧管理 ✅ 已沉淀（基于贵州宏立城用例）

> 场景类型 = **流程协同 + 数据分析**（资产台账 + 状态流转 + 折旧计算 + 报废闭环 + 看板）。属"人力/行政"大类下的资产管理子场景。适用于任何有大量固定资产需要台账化、折旧核算、领用流转、报废下账的中大型组织（集团、园区、学校、医院、连锁等）。

### ⚠️ 这个用例的头号教训：知识库可能与本次场景完全错配
宏立城挂的是「金融服务（汽车贷款担保/助贷）」知识库，实际需求却是**集团内部行政固定资产管理**，两者毫不相关。
- **以 B（沟通记录）为唯一权威**，知识库 A 仅在确实同主题时才参考；主题不符时**直接弃用 A**，绝不能拿"助贷/订单/三向资金"那套硬套到固定资产上。
- 搭建 Prompt 的"注意事项"里应显式写明："不要使用 {错配知识库行业} 知识生成本项目表结构；本项目是 {真实场景}。"

### 核心流程节点
建台账（一级库/二级库 Excel 搬线上）→ 领用/借调/调拨流转 → 按月自动折旧 → 盘点调整（多退少补）→ 状态变更（闲置/损坏）→ 报废处置 → 下账闭环

### 角色
- 全员：提交领用/借调/调拨记录、查看本人相关与可领用资产基础信息
- 行政：维护资产台账、领用记录、报废状态（核心维护方）
- 财务：维护折旧规则与净值核算、报废下账、敏感字段独享
- 部门负责人：查看本部门资产
- 管理层：看全局统计，不录入

### 五张表结构（核心主表 + 流转表 + 规则表 + 组织辅助表 + 看板）
| 表 | 类型 | 用途 |
|---|---|---|
| **固定资产库** | 核心主表 | 登记资产信息/分类/折旧/状态/当前所在部门/流转记录（23 字段，按组分块） |
| **领用管理** | 流转表 | 记录领用/借调/调拨，回写资产库，**历史追加不覆盖** |
| **资产折旧库** | 规则表 | 维护物资分类↔折旧年限（建筑类20年/生产设备10年/运输工具4年…） |
| **部门库** | 组织辅助表 | 人员↔部门映射，对齐企业微信组织架构 |
| **数据看板** | 仪表盘 | 资产数量/状态/净值/部门分布/报废处理 |

### 关键技术范式 ①：按月折旧公式字段链（全新，务必掌握）
```
物资分类 →(关联资产折旧库)→ 年限
可用月   = 年限 × 12
使用月数 = 当前年月 − 入司年月
月折旧率 = 1 / 可用月（或单价/可用月，按客户口径）
目前净值 = 单价 − 单价 × 已用月占比，且【不低于 0】
```
- 折旧粒度：**按月**（客户明确否定按年，"按年值折旧范围太大"）
- 残值率/特殊折旧规则：客户没提的一律标 ⚠️ 待确认，不臆造

### 关键技术范式 ②：状态驱动 + 流转留痕不覆盖 + 报废下账闭环
- **资产状态枚举**：公用 / 个人 / 闲置 / 损坏 / 报废（统一用词）
- **流转类型枚举**：领用 / 借调 / 调拨（统一用词）
- 领用提交 → 自动回写资产库"目前所在部门""最新领用时间""领用记录"；**领用记录持续追加，不覆盖历史**（客户原话："不会覆盖，一直滚动"）
- **报废下账闭环**：状态改"报废" → 自动移出"在用资产视图" → 进入"报废汇总视图"（筛选：状态=报废 且 是否处理=否）→ 勾选"是否处理"= 完成下账 → 从汇总视图消失。这就是客户要的"处置后不在账上体现"。

### 关键字段与录入特征
- **固定资产库字段分组**（23 字段）：资产基础（所在部门/编号/名称）｜资产分类（物资分类/分类名称）｜规格信息（品牌/规格/型号/出厂编号/单位）｜金额折旧（单价/年限/可用月/入司时间/使用月数/月折旧率/目前净值）｜状态流转（资产状态/最新领用时间/领用记录）｜报废闭环（是否处理）
- **字段优先对齐客户现有 Excel 表头**（客户已确认"按现在使用的表单字段设置"）——不要自作主张换字段名
- 关联带出：选物资分类→带出年限；领用选资产→带出编号/单价；选领用人→带出部门
- 部门优先对齐**企业微信组织架构**（客户原话："企微里面有架构"）

### 视图设计（固定资产库）
全部资产 / 在用资产（状态≠报废）/ 报废汇总（状态=报废且未处理）/ 按部门分组

### 数据看板常用 KPI
- 资产总数 / 在用 / 闲置 / 损坏 / 报废 / 资产净值
- 各部门资产数量 / 总净值 / 最新流转
- 报废资产数 / 未处理数 / 处理完成数 / 待处理天数

### 一期 / 二期边界（典型）
- **一期**：固定资产库 + 领用管理 + 资产折旧库 + 部门库 + 数据看板
- **二期/暂不**：用车用章会议室等行政审批线上化、二维码/PDA 盘点、与 ERP/财务系统折旧凭证对接、AI 问数。**不替代完整固定资产财务系统**。
