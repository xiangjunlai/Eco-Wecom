# 搭建 Prompt 文件生成规则

> 第 ④ 份交付物：教客户/实施团队"怎么在真实平台搭这个智能表格/应用"的 Markdown 文档。

## 何时生成

只有以下场景类型才生成第 ④ 份：
- **数据分析**：需要在企业微信内搭智能表格 + 数据看板
- **流程协同**：需要在企业微信工作台搭建自建应用
- **客户/销售**：需要搭轻量 CRM（企业微信智能表格）
- **积分/激励**：需要搭多表关联的积分账户 + 奖品库存闭环（**必须含"表间关联关系"和"一期/二期范围"两章**）

> **平台铁律**：搭建对象只能是企业微信生态（智能表格 / 智能机器人 / 自建应用 / 微盘），**绝不写钉钉、飞书等友商平台**。

**纯咨询、培训、战略规划类需求不需要第 ④ 份。**

## 文件格式

- 文件类型：`.md`（Markdown）
- 文件名：`{客户名简称}_智能表格搭建Prompt.md`
- 或：`{客户名简称}_{场景}搭建Prompt.md`（按场景命名）

## 必备章节（8 个，按顺序）

### 1. 概述
- 一段话讲清"这份 Prompt 是干什么的"
- 适用平台：**企业微信**（智能表格 / 智能机器人 / 自建应用 / 微盘），不涉及任何友商平台
- 目标读者：客户实施团队 / 客户 IT / 内部运维

### 2. 前置准备清单
- 需要的账号 / 权限
- 需要准备的素材（Logo、字段定义表）
- 环境要求

### 3. 智能表格搭建步骤（核心）

按"步骤 → 操作 → 截图说明 → 验证"四列结构：

```markdown
### 步骤 1：创建数据源
1. 登录企微管理后台
2. 进入「应用 → 智能表格」
3. 点击「新建」→「空白表格」
4. 命名为「{数据源名}」
5. **验证**：表格创建成功
```

每一步必须：
- 路径明确（菜单层级不超过 3 层）
- 操作具体（点击什么按钮）
- 有验证标志（怎么确认这步成功）

### 4. 字段定义表

**这是核心**。把所有 xlsx 的字段以表格形式列出：

| 字段名 | 字段类型 | 是否必填 | 数据验证 | 默认值 | 权限范围 |
|---|---|---|---|---|---|
| 订单号 | 单行文本 | 是 | 唯一 | — | 全员 |
| 客户 | 关联字段 | 是 | 引用客户表 | — | 全员 |
| 状态 | 单选 | 是 | 下拉枚举 | 待确认 | 全员 |
| 总金额 | 数字 | 是 | > 0 | — | 财务+老板 |
| ... | ... | ... | ... | ... | ... |

### 4.5 表间关联关系（多表场景**必备**）

> 只要场景含**多张表 + 自动汇总**（积分累计、库存增减、排行榜），就必须有这一节。单表场景可跳过。

逐条列出每个关联，写清 6 要素：

| 主表 | 关联表 | 关联字段 | 汇总/引用方式 | 自动带出/计算内容 | 目的 |
|---|---|---|---|---|---|
| 改善提报表 | 人员积分表 | 提报人 | lookup | 带出提报人所在部门 | 减少手填、避免填错 |
| 人员积分表 | 改善提报表 | 姓名←提报人/落实人 | rollup（sum 积分） | 累计获得积分 | 积分自动累计 |
| 人员积分表 | 奖品领取表 | 姓名←领取人 | rollup（sum 消耗积分） | 已用积分 | 自动扣减 |
| 人员积分表 | （表内公式） | — | 公式 | 可用积分=累计−已用 | 实时余额 |
| 奖品库存表 | 采购入库表 | 奖品名 | rollup（sum 入库数量） | 库存增加 | 入库自动补库存 |
| 奖品库存表 | 奖品领取表 | 奖品名 | rollup（count/ sum） | 库存减少 | 兑换自动扣库存 |

**搭建说明必须配套**：每条关联在"搭建步骤"里要有对应的"如何在平台配置该 lookup/rollup 字段"的操作说明。

### 5. 视图配置

把 xlsx 的每个 Sheet 转化为**视图**配置：

- 看板视图（数据看板对应）
- 表格视图（订单总览对应）
- 甘特图视图（实施计划对应）
- 日历视图（如适用）
- 画廊视图（如适用）

每个视图：
- 数据源
- 显示字段
- 排序规则
- 筛选条件
- 分组方式

### 6. 权限配置

按角色配权限：

| 角色 | 可见表 | 可编辑字段 | 不可见字段 |
|---|---|---|---|
| 客户（业务） | 全部 | 客户档案、订单总览（部分） | 财务字段 |
| 跟单员 | 全部 | 订单总览、打样进度 | 财务完整数据 |
| 财务 | 财务、订单总览 | 全部财务字段 | 客户档案详细 |
| 老板 | 全部 | 全部 | — |

### 7. 自动化规则

- 状态变更通知：什么状态变了推送给谁
- 超期催办：什么算超期，推送给谁
- 收款提醒：到期前几天提醒
- 关键词触发：检测到 X 关键词自动打标签

每个规则：
- 触发条件
- 触发动作
- 推送对象
- 频率限制

### 8. 测试用例

提供 3-5 个**端到端测试用例**：

```markdown
### 用例 1：新增订单流程
1. 业务在「订单总览」点击「新建」
2. 填写订单号 PO-2026-001、客户、金额
3. 状态选择"待确认"
4. **预期**：订单出现在列表，状态为"待确认"；触发通知给跟单员
```

### 8.5 一期 / 二期范围划分（多模块场景**必备**）

> 客户最关心"先上什么、什么时候能用"。明确范围能避免一次性堆功能导致上线延期。

用表格区分两期，标清交付边界：

| 功能模块 | 一期（先交付） | 二期（后续迭代） | 说明 |
|---|---|---|---|
| 改善提报 + 审核 | ✅ | — | 核心闭环，必须先上 |
| 人员积分自动累计 | ✅ | — | 一期核心价值 |
| 奖品库存 + 兑换闭环 | ✅ | — | 一期核心价值 |
| 部门/个人排行榜看板 | ✅ | — | 一期可视化 |
| 积分规则可视化配置 | — | ✅ | 一期先固定规则 |
| 移动端推送提醒 | — | ✅ | 一期先用平台默认通知 |
| 改善成效 BI 分析 | — | ✅ | 数据积累后再做 |

**写作要点**：
- 一期 = 跑通核心业务闭环 + 关键自动化，**让客户最快用起来**
- 二期 = 锦上添花的配置化、分析、集成能力
- 每项标"✅ / —"，并在"说明"列写清为什么放这一期

### 8.6 命名规范（多表场景**必备**）

避免实施团队各自命名导致字段对不上、关联配错：

- **表名**沿用 xlsx 既有命名，不擅自改名
- **状态字段**用明确枚举，不用自由文本（如"审批通过/退回/重填"而非随手写）
- **金额字段**统一用金额类型，统一 `¥ #,##0.00`
- **人员字段**统一用平台"人员"类型（关联企业通讯录）
- **关联字段**（经销商/产品/渠道）统一用"关联记录"并支持搜索
- **自动化规则名**要体现"触发条件 + 通知对象"（如"放款成功通知业务员"）
- **资金/敏感字段**集中命名、集中分组，方便统一配权限

### 8.7 搭建注意事项（落地避坑）

把实施时容易踩的坑提前写清：

- 哪些**不要写入一期**（如 AI 判断、复杂结算引擎）
- 复杂规则一期先"记录 + 汇总"，不强行做成自动公式
- 候选项多的关联字段（几百家经销商）必须**搜索选择**，不要全量铺开
- 权限必须按角色隔离（谁看本人、谁看下属、谁看待办、谁看资金）
- 可配置阈值（如归档超期天数）要说明默认值
- 附件多时提醒评估文档/微盘空间
- 字段调整应支持低成本修改，打消客户"改字段要再收费"的顾虑

### 9. 上线 Checklist

- [ ] 所有表创建完成
- [ ] 所有视图配置完成
- [ ] 所有权限测试通过
- [ ] 所有自动化规则测试通过
- [ ] 至少 5 个测试用例全部通过
- [ ] 培训材料准备完成
- [ ] 备份机制就绪

### 10. 常见问题 FAQ

至少 5 条 Q&A：
- 字段名能不能改？
- 视图可以分享给客户吗？
- 自动化规则触发频率怎么调整？
- 历史数据怎么导入？
- 权限可以细分到字段吗？

## 写作风格

- **命令式但友好**：用"点击""选择""输入"等动词
- **路径层级明确**：菜单不超过 3 层
- **验证标志**：每步有"✅ 验证：xxx"
- **截图位**：用 `[截图：xxx]` 标注截图位置
- **总长度**：30-80 分钟阅读量（约 5000-10000 字）

## 反例（绝对禁止）

- ❌ **出现钉钉、飞书、宜搭、多维表格、Lark、Notion、Airtable 等友商平台**——只能写企业微信
- ❌ 写"在企微/钉钉/飞书里..."这种含糊措辞——平台恒定为企业微信，菜单路径必须是企业微信真实路径
- ❌ 步骤过于简略（"建一个表格"——必须在哪个菜单点哪个按钮）
- ❌ 没有字段类型和验证规则
- ❌ 没有权限配置章节
- ❌ 没有测试用例
- ❌ 没有 FAQ
