## 1. ⛔ 绝对不能改的（锁死项）

### HTML（5个视觉基因，改了就掉档）

1. **主色 `#1677ff` 企业微信蓝 + 光晕背景**
   `body` 的 `radial-gradient` 光晕 + 线性渐变，整段 `<style>` 一个字符都不要动。
2. **Hero 右侧「仿真经营看板」**
   左文案右看板的两栏布局。看板里必须有：3个 KPI卡 + 迷你数据表（带彩色 `tag`：green/blue/orange）。
3. **04章「分层架构图」**
   4个横向 `layer`，左侧蓝色 `label` + 右侧 4个 `cell`。固定四层：业务录入层 / 智能表格层 / 看板分析层 / 扩展能力层。
4. **03章「厚 module 场景卡」**
   每个场景 = 左侧大序号 `module-side` + 右侧三点钉 `points`（数据源/维度/使用对象）+ 价值行。禁止退化成一句话的扁平卡。
5. **章节用「英文 kicker + 中文大标题」**
   `01 / Stage`、`02 / Insight`…… 英文编号固定，13节顺序不可删。

### Word（4个结构基因）

1. **企业微信蓝表头**：所有表第一行 `#1677FF` 底 + 白字加粗。
2. **11节主结构**：一~十一节标题 + 蓝色下划线，顺序与编号锁死。
3. **25张表骨架 + 表头文字**：表头列名锁死。
4. **浅蓝斑马行 `#F1F8FF`**：偶数行底色，保持可读性。

## 2. ✅ 必须做的（填充项）

- 把所有 `{{双花括号}}` 替换成**来自客户材料的真实内容**。
- 数据行可按真实信息**增减**（场景卡 2~4个、痛点 3~5条），但每区块不得少于模板给的最小条数。
- Hero 看板的 KPI 和数据表，用客户业务里真实的指标名 + 合理估算数值（如"本月上门 128 / 签约 36 / 产值 ¥86万"）。
- 客户已有系统的只读源数据底表，沿用标杆命名法：**`禁止修改！客户`、`禁止修改！合同`**。

## 4. v11 新增板块特别规则

### 08 经营看板效果预览（纯 CSS/SVG 手绘）
- 必须含 2~3 类图表：饼图/环形图、双柱对比图、横向条形图、实施前后对比条
- 数据为示意需标"示意数据"；配色沿用主色（#1677ff / #21c8f6 / #17b26a / #f79009）
- SVG path 扇形用手绘方式，不依赖外部库

### 07 数据蓝图（字段归 Step5）
- `dataBlueprintNote` 必须说明"具体字段将在方案确认后的智能表格搭建环节（Step5）展开"
- 只列**表名 + 用途 + 使用角色**，禁止列字段名、类型、公式

### 12 落地共创信任状
- `trust` 渐变区必须写清"30-50%现场调整正常且负责任"
- `steps` 四步固定：需求共创 → 字段定准 → 原型试跑 → 定稿上线

## 5. 三份标杆为什么好（提炼出的"做得最好的点"）

1. **诊断式开场**：不一上来堆功能，而是先做"客户阶段判断"——告诉客户"你现在缺的不是系统，是数据层"，显专业。
2. **Hero 看板可视化**：右侧仿真看板让客户一眼看到"做完长这样"，比纯文字有说服力。
3. **场景三点钉**：每个场景都点明"数据源/维度/使用对象"，让客户知道方案落到谁身上。
4. **分层架构图**：把"业务录入→智能表格→看板→扩展"的链路画清楚，体现轻量、不重建的交付理念。
5. **边界感**：反复强调"不替代原系统、不重建 CRM、只做前端看板"，控制项目范围、降低客户决策门槛。
6. **Word 的 25表闭环**：从基础信息一路到报价口径、变更机制、签署，是可直接拿去和客户对齐的交付物。

照着模板填，这 6 点就自动保留下来了。
