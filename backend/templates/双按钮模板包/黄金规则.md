# 黄金规则说明 · 两个按钮的产物质量底线

> 给「售前解决方案」和「技术路线及报价方案」两个按钮背后的 agent / minimax 看。
> 一句话目标：**照着模板骨架填业务内容，把三份标杆（城邦美商 / 省心住 / 亿选装饰）的最佳实践锁死，质量下限拉到标杆水平。**

---

## 0. 两个按钮各用哪个模板

| 按钮 | 产物 | 用模板 |
|---|---|---|
| 售前解决方案 | HTML 可视化方案 | `templates/售前解决方案_HTML模板.html` |
| 技术路线及报价方案 | Word 需求确认表 | `templates/技术路线及报价方案_Word模板.docx`（由 `scripts/生成Word模板.py` 生成） |

工作流：后端取前 3 步信息 → 拼「请严格使用本模板骨架，只替换 `{{}}` 占位符，禁止改动版式」指令 + 客户材料正文 → 传给 minimax → 产出。

---

## 1. ⛔ 绝对不能改的（锁死项）

### HTML（5 个视觉基因，改了就掉档）

1. **主色 `#1677ff` 企业微信蓝 + 光晕背景**
   `body` 的 `radial-gradient` 光晕 + 线性渐变，整段 `<style>` 一个字符都不要动。
2. **Hero 右侧「仿真经营看板」**
   左文案右看板的两栏布局。看板里必须有：3 个 KPI 卡 + 迷你数据表（带彩色 `tag`：green/blue/orange）。这是和"纯文字 Hero"拉开代差的关键。
3. **04 章「分层架构图」**
   4 个横向 `layer`，左侧蓝色 `label` + 右侧 4 个 `cell`。固定四层：业务系统层 / 智能表格层 / 看板分析层 / 扩展能力层。
4. **03 章「厚 module 场景卡」**
   每个场景 = 左侧大序号 `module-side` + 右侧标题说明 + 三个 `point` 点钉（数据源/维度/使用对象）。禁止退化成一句话的扁平卡。
5. **章节用「英文 kicker + 中文大标题」**
   `01 / Stage`、`02 / Insight`…… 英文编号固定，8 节顺序固定不可删。

### Word（4 个结构基因）

1. **企业微信蓝表头**：所有表第一行 `#1677FF` 底 + 白字加粗。
2. **11 节主结构**：一~十一节标题 + 蓝色下划线，顺序与编号锁死。
3. **25 张表骨架 + 表头文字**：表头列名锁死（如「痛点编号/痛点描述/业务影响/优先级/对应企微方案」）。
4. **浅蓝斑马行 `#F1F8FF`**：偶数行底色，保持可读性。

---

## 2. ✅ 必须做的（填充项）

- 把所有 `{{双花括号}}` 替换成**来自客户材料的真实内容**。
- 数据行可按真实信息**增减**（场景卡 2~4 个、痛点 3~5 条、字段表按实际字段铺开），但每区块不得少于模板给的最小条数。
- Hero 看板的 KPI 和数据表，用客户业务里真实的指标名 + 合理估算数值（如"本月上门 128 / 签约 36 / 产值 ¥86万"）。
- 客户已有系统的只读源数据底表，沿用标杆命名法：**`禁止修改！客户`、`禁止修改！合同`**。

---

## 3. ❌ 绝对禁止的（空壳红线）

最终产物里**不允许出现**以下任意一种，否则判为不合格、必须重写：

| 禁止物 | 例子 |
|---|---|
| 残留占位符 | `{{客户名}}`、`{客户名}`、`{行业}` |
| 空壳话术 | `（待补充）`、`（待识别）`、`（暂无）`、`XXX`、`内容内容` |
| 整段复读模板提示文字 | 把"60~120字"这种填写提示原样留在产物里 |

> 例外：08 章「待确认问题」表里的具体问题，可以写成真实问题（如"装修云管家是否支持 API 同步？"），但**问题本身必须是真实的、有信息量的**，不能是"待确认 1、待确认 2"。
> Word 里"确认结果"列允许填"待确认"——那是签署流程的正常状态，不算空壳。

自检：交付前跑 `scripts/check_placeholder.sh 产物文件`，退出码必须为 0。

---

## 4. 三份标杆为什么好（提炼出的"做得最好的点"）

1. **诊断式开场**：不一上来堆功能，而是先做"客户阶段判断"——告诉客户"你现在缺的不是系统，是数据层"，显专业。
2. **Hero 看板可视化**：右侧仿真看板让客户一眼看到"做完长这样"，比纯文字有说服力。
3. **场景三点钉**：每个场景都点明"数据源/维度/使用对象"，让客户知道方案落到谁身上。
4. **分层架构图**：把"业务系统→智能表格→看板→扩展"的链路画清楚，体现轻量、不重建的交付理念。
5. **边界感**：反复强调"不替代原系统、不重建 CRM、只做前端看板"，控制项目范围、降低客户决策门槛。
6. **Word 的 25 表闭环**：从基础信息一路到报价口径、变更机制、签署，是可直接拿去和客户对齐的交付物，而非 PPT 式空话。

照着模板填，这 6 点就自动保留下来了。
