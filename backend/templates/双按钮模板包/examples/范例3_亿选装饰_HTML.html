01 / Stage

客户阶段判断

客户不是缺少业务录入系统，而是缺少一个给老板、店长、商务负责人随时看的经营数据层。本期应做前端分析，不做全流程系统重建。

已有系统

装修云管家作为客户与合同录入来源，继续保留原有一线录入习惯。

核心对象

客户表、合同表、客户跟进记录，围绕上门与签约形成分析。

管理诉求

老板在外也能及时看上门量、渠道分布、签约产值和人员排行。

交付边界

不替代装修云管家，不重建CRM，只做智能表格前端看板。

02 / Insight

需求洞察

客户的真实需求不是“再做一套系统”，而是让已有系统数据变成管理层可理解、可下钻、可追踪的经营视图。

核心判断：先用 2 张只读底表 + 2 个核心看板，跑通管理层决策闭环。

客户明确表示目前最主要的是上门客户和签约交定两个维度，其他指标暂不复杂扩展。因此一期应聚焦最小可行看板，保证快、准、可调整。

1
一线汇报慢数据已在系统录入，但老板需要等人工汇总，时效性不足。
2
渠道贡献看不清需要知道主要进单渠道，并能按月度、年度观察变化。
3
签约排行不直观签约客户、产值、人员分布需要形成排行榜与趋势视图。
4
看板需要可下钻从汇总数字能跳回客户或合同明细，看到部门归属。

06 / Roadmap

实施路径建议

先确认同步字段和指标口径，再搭建底表、看板、权限与试跑。

第 1 阶段

字段与口径确认

确认客户表、合同表、渠道枚举、人员组织、签约金额口径。

第 2 阶段

同步底表搭建

创建“禁止修改！”客户/合同表和客户跟进记录，配置只读权限。

第 3 阶段

看板配置

配置上门看板、签约看板、设计师×渠道概览和下钻定位。

第 4 阶段

试跑与优化

用真实数据校验统计口径、权限、展示效果，并交付操作说明。

07 / Value

方案价值

用最小改造成本，把已有系统数据变成老板可随时查看、可下钻、可复盘的经营看板。

汇总更及时

减少日报与微信群人工汇总，管理层在企业微信内即可查看。

渠道更清晰

按渠道、人员、周期看上门与签约，判断获客质量和转化表现。

下钻更直接

从看板数字回到客户/合同明细，快速定位责任部门和一线人员。

保护源数据

同步底表只读，避免在智能表格侧误改造成源系统数据不一致。

上线更轻

不改变一线原录入流程，降低培训与落地阻力。

后续可扩展

可进一步加AI问数、自动月报、异常渠道预警和目标达成提醒。

08 / Confirm

待确认问题

正式实施前，需要客户确认数据同步方式、指标口径和权限边界。

问题为什么要确认优先级
装修云管家是否支持 API 同步，还是先采用导出/定时导入？影响工期、实时性和技术复杂度高
上门客户统计是否仅统计已上门，还是包含待上门/预约客户？决定上门指标口径高
签约产值用合同金额、结算金额还是收款金额？决定签约排行和产值统计口径高
