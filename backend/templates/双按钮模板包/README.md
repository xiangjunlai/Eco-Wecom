# 两个按钮接入说明（后端开发看）

本包用于在 sining.cloud 工作台实现两个按钮，让它们产出和三份标杆（城邦美商 / 省心住 / 亿选装饰）同等质量的产物。

```
双按钮模板包/
├── README.md                          ← 本文件，后端接入指南
├── 黄金规则.md                         ← 给模型看的产物质量底线（最重要）
├── templates/
│   ├── 售前解决方案_HTML模板.html        ← 按钮①用，已锁死视觉基因
│   └── 技术路线及报价方案_Word模板.docx   ← 按钮②用，11节25表骨架
├── scripts/
│   ├── 生成Word模板.py                  ← 重新生成 Word 模板（改骨架时用）
│   └── check_placeholder.sh            ← 产物空壳自检，交付前必跑
└── examples/                          ← 三份标杆成品，喂给模型当范例
```

---

## 一、核心思路：为什么这样能解决"空壳产物"

之前空壳的根因 = **拼 prompt 时只喂了规则/模板，没把客户材料正文喂进上下文**，模型无米下锅只能吐占位符。

本方案两道保险：
1. **模板锁死骨架** → 模型不用从零排版，只填内容，质量下限大幅提升。
2. **强制喂客户材料正文** → 把前 3 步的真实信息塞进 user message，模型有米下锅。

---

## 二、按钮 ① 售前解决方案（生成 HTML）

### 调用时拼的 prompt 结构

```
system（系统提示）:
  你是企业微信定制开发服务商的方案专家。请严格使用我给的 HTML 模板骨架，
  只替换 {{双花括号}} 占位符为真实业务内容，禁止改动任何 CSS/版式/配色/章节结构。
  产物中不允许残留任何 {{}} 占位符或"待补充/待识别/暂无"等空壳话术。
  务必参考我给的范例风格（Hero 仿真看板、分层架构图、厚场景卡）。

user（用户消息，三段拼接）:
  【模板骨架】
  <粘贴 templates/售前解决方案_HTML模板.html 全文>

  【客户材料正文】       ← 关键！必须喂真实材料，不能只给规则
  <粘贴前 3 步收集到的：客户名/行业/沟通记录/需求总结/痛点等全部正文>

  【参考范例】（可选但强烈建议）
  <粘贴 examples 里任一份成品 HTML，让模型对齐风格>

  【任务】
  请基于客户材料，把模板填充成完整的售前 HTML 方案。
```

### 输出后处理
- 保存为 `.html`
- 跑 `bash scripts/check_placeholder.sh 产物.html`，退出码非 0 则触发重新生成。

## 三、按钮 ② 技术路线及报价方案（生成 Word）

Word 模板是二进制 docx，模型不能直接"填 docx"。两种落地方式选一：

### 方式 A（推荐）：模型产出结构化内容 → 后端回填模板
1. 让模型按 `黄金规则.md` 的 11 节结构，输出**纯文本/JSON 的各表内容**。
2. 后端用 `python-docx` 打开 `技术路线及报价方案_Word模板.docx`，把模型返回的内容逐表回填到对应 `{{占位符}}` 单元格。
3. 这样版式 100% 锁死，模型只负责文字。

### 方式 B（简单）：模型直接产 HTML 版需求表 → 转 docx
1. 复用 HTML 思路，让模型产出一份"需求确认表" HTML（表格为主）。
2. 后端用 weasyprint / pandoc 转 docx。
3. 缺点：版式不如方式 A 可控。

> 建议先用方式 A。回填脚本可参考 `scripts/生成Word模板.py` 的 `set_cell_text` 写法。

## 四、把按钮本身做成 skill（你提到的方案）

可以让两个按钮做成 skill 触发器，skill 内部：
1. 自动拉取前 3 步信息（客户基础信息 / 沟通记录 / 需求总结）。
2. 读取本包 `templates/` 对应模板 + `黄金规则.md`。
3. 拼成上面的 prompt 调 minimax。
4. 产物跑 `check_placeholder.sh` 自检，不过则重试 1 次。

这样按钮 = 薄触发层，真正的"质量保证"在模板 + 黄金规则 + 自检三件套里。
