# 企业微信生态 · HTML《售前解决方案》生成 Skill（平台版·三件套之①）

## 概述

本技能生成一份**单文件 HTML 售前解决方案**，用于服务商向客户决策层**演示、汇报**。它对标专业交付样本（如《贝尔高林_设计景观项目管理可视化方案.html》），走**专业交付风**而非营销长文风：以客户业务为中心，结构清晰、语气克制、用适度的可视化辅助表达，不做夸大促销。

> 本技能是售前三件套的一员，遵守 `../README.md` 中的全套件共享规范（服务商变量化 / 客户不脱敏 / 一期二期边界 / 去营销化）。

---

## ⭐ 生成前必须确认

### 服务商变量

| 变量 | 含义 | 示例 |
|------|------|------|
| `{{SP_NAME}}` | 服务商品牌/简称 | 西安转悦电子科技 |
| `{{SP_FULL_NAME}}` | 服务商工商全称（头部署名 + footer 署名用） | 西安转悦电子科技有限公司 |

> 未提供的变量保留 `{{占位符}}` 原样输出。

### 客户需求理解

按 `../README.md` 第二节，从需求沟通记录 + 服务商总结 + 行业知识中提炼统一口径（客户画像、痛点、场景、表清单、字段、关联、权限、自动化、看板、一期/二期边界）。HTML 是这份理解的"可视化呈现层"，内容必须与同套件 Word / Prompt 产物口径一致。

---

## 一、输出规格（硬性）

- **单文件**：一个 `.html`，所有 CSS 内联在 `<style>`，所有图表用**内联 SVG**，**零外部依赖**（不引 CDN、不引图片、不引字体文件）。
- **生成方式**：HTML **一次性完整写入**，不用 Python 拼接、不分块追加。
- **文件命名**：`{客户全称}_{方案主题}.html`，如 `贝尔高林_设计景观项目管理可视化方案.html`。
- **输出位置**：`/workspace`（用户可见）。
- **响应式**：`@media(max-width:900px)` 下多列网格降为单列。

---

## 二、7 章固定结构

| 章 | 标题 | 内容要点 | 建议可视化 |
|----|------|----------|-----------|
| 01 | **需求洞察** | 3 张痛点卡片，每张：痛点标题 + 业务描述（从现状提炼，不照抄原话） | 可选 1 个 SVG 图表 |
| 02 | **方案定位** | 2 张卡：一期建设目标 + 边界控制（哪些能力进二期评估） | 可选能力架构示意 |
| 03 | **建议建设模块** | 每张智能表一行 module 卡：表名（中英）+ 用途 + "一期必做/二期"标签 | 表清单成列表 |
| 04 | **自动化与权限** | 2 张卡：自动化提醒（触发条件列表）+ 权限原则（按角色/区域隔离） | 可选权限矩阵简表 |
| 05 | **实施路径** | 4 步时间轴：字段确认→智能表搭建→自动化配置→试运行交付 | 时间轴 4 列 |
| 06 | **方案价值** | 4 张数字大卡 metric：表数量 / 关键阈值 / 多币种或多区域 / 权限维度 | 数字大卡 4 列 |
| 07 | **待确认问题** | 6 条左右待客户确认问题 + 结论段（**专业总结，无营销 CTA**） | 列表 |

> 章节编号 `01`–`07` 写在 `<h2>` 中。每章用 `<section>` 包裹，给关键章加 `id`（如 `#insight #module #roadmap #confirm`）供导航锚点跳转。

## 三、全局样式与组件规范

### 3.1 头部（hero）

以**客户为中心**，包含：

- `eyebrow`：客户全称 + 行业（如 `BeltCollins 贝尔高林｜设计/景观建筑`）
- `h1`：方案主题（如 `跨国多区域项目管理智能表格解决方案`）
- 一句话定位段：概括方案做什么（企业微信入口 + 智能表格数据底座 + 自动化 + 权限 + 看板）
- `tags`：关键标签（规模 / 区域 / 场景 / 特性，如"约50人""多币种""中英文协同"）
- 右侧可选 `mock` 面板：模拟仪表盘缩略图（几行带进度条的 minirow）

### 3.2 导航（nav，sticky）

顶部 sticky 导航条：左侧 logo（"企"字标 + "企业微信服务商定制开发售前方案"），右侧锚点链接指向主要章节。`position:sticky; top:0`。

### 3.3 署名

- 头部或 footer 出现乙方署名："由 `{{SP_FULL_NAME}}` 提供" + 输出日期。
- footer 结论区可署 `{{SP_FULL_NAME}}`。
- **只露出乙方企业全称**，不加"认证服务商"等前缀，不写服务热线 / 邮箱 / 追踪域名。
- **日期来源（强制）**：输出日期**默认自动获取生成当天的真实日期**，格式 `YYYY年MM月DD日`（可用 `new Date()` 或生成时直接写入当天日期字符串）。调用方如显式传入指定日期则以传入值为准。不要留空占位。

### 3.4 水印（保留）

全屏灰色平铺水印，**默认文字固定为 `企业微信生态定制开发`**（不使用占位符，不写服务商名）。建议实现：

```css
body::before{
  content:"企业微信生态定制开发"; position:fixed; inset:0; z-index:0;
  pointer-events:none; color:rgba(0,0,0,.045); font-size:34px; font-weight:800;
  /* 通过重复 content / 多层背景实现平铺；正文容器 z-index 高于水印 */
}
```

> 如需更密集铺满，可用一个 `position:fixed` 全屏层 + `repeating` 文本或多行 `<div>` 平铺，透明度控制在 4%–10%，不干扰阅读。

### 3.5 配色与卡片

参考范例 `:root` 变量：主蓝 `#1476ff`、深色 `#10233f`、灰字 `#65758b`、浅底 `#f3f7ff`、绿色 `#17b26a`。卡片白底 + 浅边框 + 柔和阴影 + 大圆角（18–24px）。

## 四、图表规范（按需，不设硬性数量）

> ⚠️ **重要冲突裁决**：本技能**不沿用**旧版"必须≥6 SVG / ≥6 数字卡 / ≥6 进度条 / ≥4 对比卡"的硬性数量要求。以专业交付范例为准——图表**按需适度点缀**即可，01/03/06 章有少量可视化即可，宁缺毋滥。

- 所有图表必须是**内联 SVG**，零外部依赖。
- 常用：进度条（module 旁）、数字大卡（06章 metric）、简单柱状/环形示意。
- 不为凑数硬塞图表；图表必须服务于表达，否则用文字/表格。

---

## 五、内容纪律（去营销化）

对标专业交付范例，**严格遵守**：

- ❌ 不做 ROI 算钱章、不做三档报价促销章、不做"标杆案例/避坑指南"章、不做服务保障承诺章
- ❌ 不嵌入任何访问追踪代码（上报域名 / 点击像素 / tracker.php）
- ❌ footer / 正文不出现隐私声明、第三方追踪域名、追踪邮箱
- ❌ 不写服务热线 / 客服电话
- ✅ 客户信息真实呈现，不脱敏
- ✅ 未经客户确认的能力（OA 对接 / 机器人写表 / AI）一律在 02 章边界控制和 07 章待确认问题中标注"**二期评估 / 待确认**"
- ✅ 07 章结论段是专业总结（方案如何以核心表为中心解决问题），**不是**"立即联系我们"式 CTA

## 六、生成步骤

1. 确认服务商变量 `{{SP_NAME}}` / `{{SP_FULL_NAME}}`。
2. 提炼客户需求理解（见 README 第二节），明确表清单、痛点、一期/二期边界。
3. 按 7 章结构组织内容，把表清单填入 03 章、痛点填入 01 章、价值数字填入 06 章、待确认项填入 07 章。
4. 一次性写出完整单文件 HTML 到 `/workspace`，含 sticky 导航、水印、内联 SVG。
5. 自检（见下），通过后向用户展示结果。

---

## 七、生成后自检清单

- [ ] 单文件、零外部依赖（无 CDN / 无外链图片字体）
- [ ] 7 章齐全，编号 01–07，关键章有锚点且导航可跳转
- [ ] 头部以客户为中心 + 乙方署名 `{{SP_FULL_NAME}}` + 输出日期
- [ ] 输出日期为生成当天的真实日期（`YYYY年MM月DD日`），未留空占位
- [ ] 水印文字为"企业微信生态定制开发"（非服务商名、非占位符）
- [ ] 客户信息真实未脱敏；服务商品牌均为 `{{占位符}}`
- [ ] 无追踪代码、无隐私声明、无服务热线、无营销 CTA
- [ ] 未确认能力均标注"二期评估/待确认"
- [ ] 表清单 / 字段口径与同套件 Word、Prompt 产物一致
- [ ] 移动端单列正常

## 八、对标范例

`/root/uploads/...贝尔高林_设计景观项目管理可视化方案.html` —— 7 章专业交付风的标准样本。生成时结构对标它，但**内容必须按目标客户行业重新提炼**，不得照搬设计行业字段。
