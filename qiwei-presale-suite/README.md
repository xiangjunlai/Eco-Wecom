# 企业微信生态 · 售前交付三件套技能套件（平台版·通用）

## 一、这是什么

本套件由**企业微信生态平台方**统一提供，供生态内**任意服务商**在售前阶段使用。它把过去"只产 HTML 营销长文"的单一技能，升级为对标专业交付标准的**三个独立技能**，覆盖售前交付的完整闭环：

| 技能 | 产物 | 格式 | 给谁看 | 用途 |
|------|------|------|--------|------|
| **① 1-solution-html** | 《售前解决方案》 | `.html` | 客户决策层 | 演示/汇报，建立信任、展示价值 |
| **② 2-techplan-word** | 《需求确认与方案设计表》 | `.docx` | 客户对接人/双方签署 | 正式确认需求边界、字段、报价口径 |
| **③ 3-smarttable-prompt** | 《智能表格Demo搭建Prompt》 | `.md` | AI / 搭建工程师 | 可执行指令，直接生成可导入企微的智能表 |

> 三技能可**独立调用**，也可**串联使用**。无论哪种调用方式，它们共享同一份"客户需求理解"，保证三个产物的**表结构、字段、阶段口径、一期/二期边界完全一致**。

---

## 二、共享的"客户需求理解"（三技能的共同底座）

三个技能都以同一份需求理解为输入。生成任何产物前，先从以下材料中提炼这份理解：

1. **需求沟通记录**（会议转写 / 客户原话）—— 提炼痛点、原话、业务现状
2. **服务商对客户的需求总结** —— 提炼场景判断、交付物清单、一期/二期边界
3. **行业知识库 / 已有表格材料（如 xlsx）** —— 提炼字段、表结构、行业术语
4. **客户基础信息** —— 客户全称、行业、规模、对接人

提炼出的统一口径包含：

- **客户画像**：全称、行业、规模、区域、协同语言
- **核心痛点**（按 P0/P1/P2 优先级）
- **场景判断**：主场景 + 辅助场景
- **智能表清单**：哪些表、表类型、是否一期必做
- **核心字段**：每张表的字段名/类型/必填/维护角色
- **表间关联**：主表↔关联表、关联字段、自动带出内容
- **权限矩阵**：角色 × 查看范围 × 可编辑字段 × 敏感字段
- **自动化与看板**：触发条件、提醒对象、看板指标
- **一期/二期边界**：一期承诺 vs 二期评估（关键！见下）

## 三、推荐执行顺序

虽然三技能可独立调用，但**串联使用时推荐顺序**：

```
② Word 需求确认  →  ③ Prompt 表设计  →  ① HTML 可视化
   (先定边界)        (再精确表结构)       (最后做演示)
```

理由：
- **先 ② Word**：把需求、字段、一期/二期边界、报价口径正式落定，这是后两者的事实基础。
- **再 ③ Prompt**：基于已确认的表结构，写出字段类型/视图/关联/权限都精确可执行的搭建指令。
- **最后 ① HTML**：把已经定稿的内容做成给客户演示的可视化方案，三者口径天然一致。

> 若服务商只需要其中一个产物，直接调用对应技能即可，三技能都内置了"从原始材料提炼需求理解"的步骤，不依赖其他技能的产出。

## 四、全套件共享规范（三技能强制遵守）

### 4.1 服务商品牌变量化

技能本体**绝不硬编码任何具体服务商**的真实品牌名、域名、电话。所有服务商露出统一用占位符：

| 变量 | 含义 | 示例 |
|------|------|------|
| `{{SP_NAME}}` | 服务商品牌/简称（正文【】标注用） | 西安转悦电子科技、XX企微管家 |
| `{{SP_FULL_NAME}}` | 服务商工商全称 | 西安转悦电子科技有限公司 |
| `{{SP_CONTACT}}` | 服务商侧对接人（可选） | 张工 |

> 服务商调用技能时填入自己的信息；未提供的变量保留 `{{占位符}}` 原样输出。

### 4.2 客户信息真实呈现，不脱敏

客户公司全称、对接人姓名、行业等**均显示真实信息**，不做任何打码 / XX 替换。

### 4.3 行业适配，不写死

行业、表结构、字段一律从需求记录 + 行业知识提炼。范例中的"贝尔高林（设计/景观）"只是示例，**不得把设计行业的字段照搬到其他行业**。

### 4.4 一期/二期边界（最重要的纪律）

未经客户明确确认的能力，**一律标注"二期评估 / 待确认"，不得写入一期承诺**。典型需要降级到二期的能力：

- OA / ERP / CRM 系统 API 对接或自动同步（需确认接口能力、字段范围、同步频率、责任人）
- 企业微信机器人自动写表 / 自动更新状态（需先做能力验证）
- AI 智能填报、AI 问数、异常检测、资源优化建议
- 涉及薪资的成本/预算深度核算（薪资数据外部计算后录入）

### 4.5 内容纪律（对标专业交付，去营销化）

- ❌ 不做夸大的 ROI 算钱、不做三档报价促销、不做"标杆案例/避坑指南"等营销章节
- ❌ 不嵌入任何访问追踪代码（上报域名 / 点击像素）
- ❌ footer / 文档中不出现隐私声明、第三方追踪域名、追踪邮箱
- ✅ 报价一律用"报价口径"表达（费用模块 + 是否包含 + 备注），不写死具体数字，除非客户已确认
- ✅ 语气专业、克制、以客户业务为中心

### 4.6 输出日期规范（三技能强制）

- 产物中的"输出日期 / 生成日期 / 编制日期"等，**默认自动获取生成当天的真实系统日期**填入，格式统一为 `YYYY年MM月DD日`。
  - HTML：用 `new Date()` 取当天，或在生成时直接写入当天日期字符串。
  - Word：用 `datetime.now().strftime('%Y年%m月%d日')` 取当天填入。
  - Prompt 文档：在文档头部写入生成当天日期。
- 调用方如显式传入指定日期参数，则以传入值为准（覆盖当天）。
- **不要留 `{{占位符}}` 或 `____` 空着交人工填**——除非调用方明确要求不填日期。
