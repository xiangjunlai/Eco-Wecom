## 概述

本技能生成一份**正式的 Word 文档**（真正的 `.docx`，含可编辑表格），用于服务商与客户**确认需求边界、字段、流程、权限、报价口径**并签署。它对标《企业微信定制开发_需求确认与方案设计表模板》，是售前阶段最正式的事实文档。

## 三、内容纪律

- **客户信息真实**，不脱敏。1.1 表填客户真实全称、行业、对接人。
- **服务商名称**填 `{{SP_FULL_NAME}}`（或已确认的真实名）。
- **业务语言翻译**：1.3 痛点、3.1 需求项必须把客户原话**转成业务语言**，不照抄原话（原话只放在 1.2 / 3.2 的"依据/原话"列）。
- **一期/二期纪律**：OA/ERP/CRM 对接、机器人写表、AI 能力、薪资成本核算等未确认能力，在 2.2 / 9.1 标注"二期可扩展 / 二期评估"，不写入一期承诺。
- **报价去促销**：10.2 只写费用模块 + 是否包含 + 备注口径，不编造三档套餐、不写死金额。
- **待确认事项**：凡是未经客户确认的设计，在 11.1 列为待确认问题，不在正文当成既定事实。

## 四、生成实现（python-docx）

用脚本生成，要点：

1. **标题区**：大标题"企业微信定制开发 / 需求确认 & 方案设计表" + 副标题 + 填写说明段。
2. **节标题**：用 `add_heading(level=1)` 写"一、…"，`level=2` 写"1.1 …"。
3. **每个表**：`add_table(rows, cols, style='Table Grid')`，首行为表头（加粗），其余行填内容。
4. **表格样式**：统一 `Table Grid`，表头行加粗、可设浅灰底纹。
5. **保存**：`doc.save('/workspace/{客户全称}_需求确认与方案设计表.docx')`。

参考骨架：

```python
from docx import Document
from docx.shared import Pt, RGBColor
from docx.enum.text import WD_ALIGN_PARAGRAPH

doc = Document()

# 标题
t = doc.add_paragraph(); t.alignment = WD_ALIGN_PARAGRAPH.CENTER
r = t.add_run("企业微信定制开发\n需求确认 & 方案设计表"); r.bold = True; r.font.size = Pt(20)
sub = doc.add_paragraph("适用于服务商基于客户基础信息与会议转写输出正式售前需求确认文档")
sub.alignment = WD_ALIGN_PARAGRAPH.CENTER
doc.add_paragraph("填写说明：本文档基于客户基础信息、会议原文与已有材料编制；未经客户确认的内容标注为'待确认'或'二期建议'，不写入一期承诺范围。")

def add_table(headers, rows):
    tb = doc.add_table(rows=1, cols=len(headers)); tb.style = 'Table Grid'
    for i, h in enumerate(headers):
        c = tb.rows[0].cells[i]; c.text = ''
        run = c.paragraphs[0].add_run(h); run.bold = True
    for row in rows:
        cells = tb.add_row().cells
        for i, v in enumerate(row):
            cells[i].text = str(v)
    doc.add_paragraph("")
    return tb

# 一、客户基础信息与当前现状
# 输出日期：默认自动取生成当天的真实日期；调用方传入指定日期则覆盖
from datetime import datetime
OUTPUT_DATE = datetime.now().strftime('%Y年%m月%d日')  # 如调用方指定日期则改为该值
doc.add_heading("一、客户基础信息与当前现状", level=1)
doc.add_heading("1.1 客户基础信息确认表", level=2)
add_table(["客户名称","内容","项目","内容"],
          [["{客户全称}","","所属行业","{行业}"],
           ["服务商名称","{{SP_FULL_NAME}}","项目场景","{主场景}"],
           ["方案版本","V1.0","输出日期",OUTPUT_DATE]])
# ... 其余 1.2 / 1.3 ... 直到 十一节，按第二节列头逐表填充

doc.save("/workspace/{客户全称}_需求确认与方案设计表.docx")
```

> 实际生成时，把每张表的真实内容（从需求理解提炼）填入，不要留占位符 `{{}}` 给客户看——除非该项确实"待确认"，此时写明"待确认"。
