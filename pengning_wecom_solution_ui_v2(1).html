01 / Background

客户阶段判断

客户已有企业微信使用基础，但订单数据仍依赖群内沟通与人工整理，当前重点不是上重型系统，而是用轻量方式把业务过程标准化。

行业金融担保 / 汽车贷款相关业务
当前工具企业微信群 + 传统表格 + 人工统计
核心角色销售、主管、中台、后台、财务、管理员
建设阶段流程规范化 + 数据可视化阶段
02 / Insight

从“做智能表格”到“重构订单协同链路”

客户的表层需求是多人录入和统计，本质上是贷款订单在不同角色之间缺少统一状态、权限边界和数据沉淀。

核心判断：一期先把订单流转跑通，二期再叠加财务复杂结算与 AI 准入辅助。

客户曾使用线下系统，但因重复录入导致业务工作量过高而停用。当前更适合用企业微信智能表格作为统一入口，让业务直接录入、中台复核、后台归档、管理层看板查看。

1
重复录入导致效率低原系统与企微使用割裂，后台人员二次整理，数据滞后且容易出错。
2
订单状态分散在多人手中接单、批复、放款、上牌、抵押、归档由不同角色反馈，缺少统一状态视图。
3
权限与数据安全需要前置设计业务员、主管、中台、后台、财务可见范围不同，需要按角色设置查看与编辑边界。
4
管理层需要按维度看经营结果需要按日/周/月，以及银行、渠道、经销商、业务员等维度统计进件和业务进度。
03 / Scenarios

核心业务场景拆解

以订单管理为主线，把录入、审核、状态、归档、统计做成一个可持续迭代的业务底座。

01

订单自助录入

P0 一期重点

业务人员直接在企微提交贷款订单

销售录入客户、贷款产品、银行、经销商、渠道商、车辆与附件等信息，减少后台代录。

现状群内反馈 + 人工整理
方案表单化录入 + 身份证识别 + 产品库选择
价值减少重复录入，提高源头数据质量
02

中台复核流转

P0 一期重点

中台对订单进行复核、通过、退回或重填

订单提交后自动通知中台，审批结果同步提醒业务人员，并进入对应状态视图。

现状状态口径依赖人工沟通
方案状态字段 + 自动提醒 + 汇总视图
价值过程可追踪，减少漏审与反复确认
03

放款与归档管理

P1 强化闭环

跟踪放款、上牌、抵押、归档及超期预警

后台/贷后人员维护后续状态，按放款时间设置归档时效，到期前提醒经办人，超期自动标记。

现状贷后进度分散反馈
方案节点字段 + 超期规则 + 自动通知
价值形成贷后闭环，降低归档遗漏风险
04

经营数据看板

P1 管理可视

按银行、渠道、经销商、业务员多维统计

按日、周、月查看进件数量、审批状态、放款情况、经销商业绩排名等关键指标。

现状人工统计耗时且滞后
方案智能表格看板 + 多维筛选
价值管理层快速掌握业务进展

05 / Modules

建议建设模块

一期优先保证订单管理闭环；财务复杂结算和 AI 判断建议作为后续迭代，避免一次性建设过重。

订单管理主表

P0

承接销售提交、中台复核、后台归档、主管查看的统一订单台账。

  • 客户信息与证件附件
  • 产品/银行/支行字段
  • 订单状态流转
  • 按角色查看与编辑权限

贷款产品库

P0

维护贷款产品与对应银行关系，减少录入时重复选择和错误匹配。

  • 产品名称维护
  • 自动带出银行
  • 产品类别字段
  • 后续可扩展准入规则

经销商/渠道商库

P1

为订单提供经销商和渠道商选择来源，并支持后续业务统计。

  • 经销商搜索选择
  • 渠道来源记录
  • 经销商进件统计
  • 权限展示策略

数据看板

P1

按业务员、银行、经销商、渠道等维度汇总订单数据，支撑管理决策。

  • 日/周/月统计
  • 进件数量统计
  • 订单状态分布
  • 经销商业绩排名

财务收付记录

P2

银行回款、经销商付款、员工提成逻辑复杂，建议先保留记录能力，后续逐步结构化。

  • 银行收款记录
  • 经销商付款记录
  • 员工提成下发
  • 应收应付辅助统计

AI 准入辅助

探索

客户希望基于贷款产品准入规则和客户信息做初步判断，建议二期以知识库和规则样例验证。

  • 产品准入知识库
  • 客户条件勾选
  • 收入负债辅助计算
  • 试点后再评估准确率
06 / Roadmap

实施路径建议

采用轻量试点方式，先跑通订单主链路，再扩展看板、权限和后续财务/AI能力。

第 1 阶段

需求确认与字段梳理

确认订单字段、角色权限、产品库、经销商库、状态口径。

交付物：字段清单、流程图、权限矩阵。
第 2 阶段

核心表格配置

搭建订单主表、产品库、状态视图、基础通知规则。

交付物：可试用 Demo、角色录入入口。
第 3 阶段

试点运行与修正

选择部分销售和中台人员试跑，调整字段、权限和提醒。

交付物：优化版本、试点问题清单。
第 4 阶段

看板与推广

上线数据看板，并逐步推广到更多业务人员与管理角色。

交付物：数据看板、培训说明、推广建议。
07 / Value

方案价值

这套方案的价值不是单点表格，而是将订单过程、角色责任和经营数据统一到企业微信内。

录
减少重复录入业务源头直接录入，后台不再承担大量二次整理工作。
流
状态流转清晰订单从提交、复核、放款到归档均有状态记录和视图承接。
权
权限边界明确不同角色看到和修改不同内容，降低订单信息乱看乱改风险。
警
超期自动提醒归档时效可按放款时间设置，减少贷后遗漏。
看
管理看板可视支持按银行、经销商、渠道、业务员等维度看进件与进度。
扩
后续可迭代财务结算、员工提成、AI 准入判断可在主数据稳定后逐步扩展。

09 / Next Questions

下一步待确认问题

这些问题会直接影响字段设计、权限配置、报价边界和交付排期。

订单字段请确认订单主表最终需要保留哪些客户信息、车辆信息、贷款信息、附件类型，哪些字段必填、哪些可后补。
角色权限销售、主管、区域负责人、中台、后台、财务、管理员分别可以查看和编辑哪些字段？是否存在跨区域查看限制？
经销商/渠道数据几百家经销商是否全部开放搜索？是否需要隐藏完整列表？是否需要按业务员或主管绑定可见范围？
归档时效放款后多少天内必须完成归档？第几天提醒？超期后是否只标记状态，还是同时通知主管/管理员？
财务边界一期是否只记录银行收款、经销商付款、员工提成下发，暂不做复杂自动计算？
AI 辅助是否可以提供贷款产品准入规则和历史样例，用于后续验证 AI 是否适合做客户准入初筛？

建议先以“订单管理主链路”作为一期建设范围

先解决业务录入、中台复核、后台归档和管理统计，再基于真实使用数据迭代财务结算与 AI 辅助能力。
