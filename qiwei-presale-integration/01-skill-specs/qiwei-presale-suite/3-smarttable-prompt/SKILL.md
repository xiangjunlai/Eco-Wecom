# 企业微信生态 ·《智能表格 Demo 搭建 Prompt》生成 Skill（平台版·三件套之③）

## 概述

本技能生成一份 **`.md` 格式的 Prompt 文档**，作为给 **AI 或搭建工程师** 的**可执行指令**，让其据此**直接搭建出可导入企业微信的智能表格 Demo**。它对标《贝尔高林_企业微信智能表格搭建Prompt.md》。

与 HTML（演示）、Word（确认）不同，本产物的读者是"执行者"，因此**字段类型、视图、关联、权限必须精确、无歧义、可直接落地**。

> 本技能是售前三件套的一员，遵守 `../README.md` 中的全套件共享规范。三者表结构/字段口径必须一致——本 Prompt 是 HTML/Word 中"智能表交付设计"的**可执行细化版**。

---

## ⭐ 生成前必须确认

- 服务商变量 `{{SP_NAME}}` / `{{SP_FULL_NAME}}`（本产物中露出较少，主要在标题/署名）。
- 客户需求理解（README 第二节），尤其是**表清单、字段、关联、权限、看板、一期/二期边界**——这是本产物的核心输入。
- 推荐在 Word 需求确认表定稿后生成，保证表结构口径一致。

---

## 一、输出规格（硬性）

- **格式**：`.md` 文件。
- **文件命名**：`{客户全称}_企业微信智能表格搭建Prompt.md`。
- **输出位置**：`/workspace`。
- **读者**：AI / 搭建工程师 → 指令必须精确可执行，**不能含模糊的占位符**（除非确属待确认项）。

---

## 二、10 节固定结构（对标范例）

| 节 | 标题 | 内容 |
|----|------|------|
| 1 | **搭建目标** | 一句话定位（企微入口+智能表数据底座+自动化+权限+看板）+ 明确**一期范围声明** + 明确**不纳入一期**的能力 |
| 2 | **一期搭建范围** | 2.1 表格清单（表名｜表类型｜用途｜使用角色｜是否一期必做）；2.2 不在一期范围内的内容 |
| 3 | **表格详细设计** | **每张表两块**：字段设计表（字段名｜字段类型｜是否必填｜维护角色｜规则说明）+ 视图设计表（视图名｜视图类型｜筛选条件｜分组方式｜可见角色） |
| 4 | **表间关联关系** | 主表｜关联表｜关联字段｜关联目的｜自动带出/汇总内容 |
| 5 | **权限设计** | 角色｜新增权限｜查看范围｜可编辑字段｜不可见敏感字段｜看板权限 |
| 6 | **仪表盘设计** | 看板名称｜使用对象｜核心指标｜筛选维度｜是否支持下钻 |
| 7 | **自动化提醒设计** | 场景｜触发条件｜提醒对象｜提醒内容｜后续动作 |
| 8 | **命名规范** | 表名/字段名/编号/视图命名约定 |
| 9 | **搭建注意事项** | 易错点、能力边界提醒（机器人/API/AI 不写成一期必交付、敏感字段单独配权限等） |
| 10 | **二期预留能力** | OA 同步、机器人写表、AI 问数、成本分析等列为二期 |

---

## 三、字段类型（必须用企微智能表合法类型）

字段类型只能从以下集合取值（精确可执行）：

`文本` / `多行文本` / `单选` / `多选` / `人员` / `日期` / `数字` / `金额` / `勾选` / `附件` / `关联记录` / `公式` / `电话` / `邮箱`

规则：
- **关联其他表的字段** → 类型必须是 `关联记录`，并在"规则说明"写明关联哪张表的哪个字段。
- **由其他字段计算得出** → 类型必须是 `公式`，并在"规则说明"写明计算逻辑（如 `开票金额 - 已回款金额`）。
- **下拉选项字段** → `单选`/`多选`，并在"规则说明"列出选项值或写明引用哪张配置表。
- **金额字段** → 用 `金额`，多币种场景保留原币 + 折算说明。

---

## 四、内容纪律

- **一期范围声明**（第 1、2 节）必须明确：哪些表/能力一期做，哪些**显式排除**（OA API 对接、机器人自动写表、AI 智能填报、薪资成本核算等）。
- **第 10 节二期预留**：把排除的能力集中列出，给客户扩展预期，但不承诺。
- **敏感字段权限**（第 5、9 节）：合同金额/开票金额/回款金额/汇率等敏感字段必须单独配权限，普通员工不可见。
- **配置表/辅助表**：阶段定义、汇率参考、省份/字典等设为配置表或隐藏辅助表，限制编辑权限。
- 客户信息真实，行业字段按目标客户行业提炼，不照搬范例（设计行业）的字段。

---

## 五、生成步骤

1. 确认服务商变量与客户需求理解（含完整表清单/字段/关联/权限/看板）。
2. 按 10 节结构组织：先写目标+范围（1、2），再逐表写字段设计+视图设计（3），再关联（4）、权限（5）、看板（6）、自动化（7），最后命名规范（8）、注意事项（9）、二期（10）。
3. 校验字段类型全部合法、关联字段双向对应、公式字段逻辑明确、敏感字段权限隔离。
4. 写出 `.md` 到 `/workspace`，向用户展示。
