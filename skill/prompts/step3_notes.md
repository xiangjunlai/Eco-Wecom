# Step 2: 沟通纪要

## 功能

收集用户上传的沟通记录，生成 **MD 题纲**。

## 触发

用户说"继续"或"下一步"，且当前上下文已有 Step 1 的客户档案时，自动进入此步骤。

## 对话流程

### 第一轮：告知用户可以上传

```
请上传沟通记录。您可以：
1. 直接粘贴文字（会议转写、聊天记录等）
2. 上传文件（.txt / .docx / .pdf）

可以多次上传，说"ok"确认上传完毕。
```

### 收集模式

用户上传内容时，将其追加到 `meeting_notes[]` 数组中。

每次上传后，询问：
```
已收到第 {n} 条沟通记录。还有吗？说"ok"确认完毕。
```

### 确认完毕

用户说"ok"（或其他确认词：好了、可以、确认完毕）后：

1. **停止收集**，不再接受新的上传
2. 将所有 `meeting_notes[]` 合并
3. 调用 AI 生成 MD 题纲
4. 展示给用户确认

### MD 题纲格式

```markdown
# 沟通纪要题纲 - {客户名称}

## 基本信息
- 客户名称：{客户名称}
- 沟通次数：{次数}次
- 沟通时间：{首次} ~ {最后}

## 沟通记录摘要

### 核心需求
{从沟通记录中提取的核心需求}

### 关键痛点
{从沟通记录中提取的关键痛点}

### 解决方案线索
{从沟通记录中提取的解决方案相关描述}

## 信息缺口（待补充）
{从沟通记录中识别出的信息缺口，对应 Step1 的 gaps}

## 下一步行动
{建议的下一步行动}
```

## AI 调用

**System Prompt:**

```
你是一个售前沟通纪要整理助手。请根据收集到的沟通记录，生成一份结构化的沟通摘要。

要求：
1. 从沟通记录中提取客户明确表达的需求和痛点
2. 标注每个信息点的来源（客户明确说的 vs 你推导的）
3. 识别出沟通记录中体现的信息缺口
4. 生成下一步行动建议

输出格式为 Markdown。
```

**User Prompt:**

```
客户名称：{client_name}
行业：{industry}

沟通记录：
{meeting_notes 的内容拼接}

请生成沟通纪要摘要。
```

## 存储

生成 MD 题纲后，将以下内容保存到上下文：

```json
{
  "meeting_notes": ["记录1", "记录2"],
  "md_outline": "生成的 MD 题纲内容"
}
```

然后询问用户是否需要微调：

```
沟通纪要题纲已生成。需要调整吗？说"没问题"或"可以"进入下一步。
```

用户确认后，进入 Step 3（需求整理）。

## Token 消耗预估

在用户说"ok"确认上传时，计算预估 Token：

```
预估 Token = (meeting_notes 总字数 + prompt 字数) × 1.5
预估费用 = 预估 Token ÷ 1000 × 0.001（元）
```

如果 Token 预估 > 5000，提示用户：
```
⚠️ 此次沟通记录较长，预估 Token：{n}，约花费 ¥{x}
确认生成 MD 题纲吗？
```
